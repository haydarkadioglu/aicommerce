     1→# AI Commerce Operating System — Worklog
     2→
     3→## Project Overview
     4→Building an "AI Commerce Operating System" — a modular SaaS platform that helps e-commerce sellers discover products, analyze markets, generate content, and make business decisions using AI. Initially Etsy-focused but marketplace-independent architecture.
     5→
     6→## Tech Stack (Decided)
     7→- **Framework**: Next.js 16 (App Router) + TypeScript 5
     8→- **Styling**: Tailwind CSS 4 + shadcn/ui (New York) + next-themes (dark mode ready)
     9→- **Database**: Prisma ORM (SQLite locally, schema portable to PostgreSQL)
    10→- **Auth**: NextAuth.js v4 (Credentials provider, JWT sessions, bcrypt password hashing)
    11→- **State**: Zustand (client), TanStack Query (server)
    12→- **AI**: z-ai-web-dev-sdk as the default provider, with provider-agnostic abstraction layer ready for OpenAI/Gemini/Claude/etc.
    13→- **Real-time**: socket.io via mini-service pattern
    14→- **UI**: Lucide icons, Framer Motion transitions, recharts for analytics
    15→
    16→## Architecture Decisions
    17→- Single-page UX: user only sees `/` (marketing landing). Auth + dashboard use modals/route state in the same page, plus a unified "App Shell" that swaps between modules.
    18→- AI requests flow through `/api/ai/*` which calls the AI Orchestrator (single entry point).
    19→- All AI providers implement a common `AIProvider` interface.
    20→- Prompts are stored in DB (editable, versioned).
    21→- Roles/Permissions use a simple RBAC model extensible for future roles.
    22→- Logging is centralized through a Logger service that writes to DB.
